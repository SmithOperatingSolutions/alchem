# Alchem compiler written in Alchem

The native compiler now rebuilds itself for the documented native source
profile. The actual assembled source produces A1; A1 produces A2; A2 produces A3.
All three generated compiler images are byte-identical, and all three pass the
integer/byte correctness and rejection suites with an empty PATH.

This is bounded self-hosting, not full production Alchem compatibility. Actors,
imports, full String APIs, macros and foreign runtime integration remain outside this
profile. Production Alchem is unchanged.

## Build and use it

```sh
bash scripts/build-native.sh
build/native/alchem-compiler < examples/alchem-byte-compiler-demo.alc > /tmp/demo
chmod 700 /tmp/demo
/tmp/demo
echo "$?"  # 42
```

The initial build needs the pinned frontend and Rust bootstrap. The resulting
alchem-compiler is A3, generated by the Alchem-written compiler itself. It needs
no Go, Rust, Cargo, Python, frontend or linker to compile source at runtime.

Build artifacts include compiler-source.alc (the exact assembled source),
self-host.json (source/stage hashes and resource profile), and
alchem-compiler-bootstrap (A0). No generated binaries are committed.

A native rebuild needs only the compiler and its source:

```sh
env -i PATH= build/native/alchem-compiler < build/native/compiler-source.alc > /tmp/rebuilt
chmod 700 /tmp/rebuilt
cmp build/native/alchem-compiler /tmp/rebuilt
```

The shell supplies files/modes; the compiler reads stdin and writes ELF stdout.
Redirection is not atomic preservation. build-self-hosted.py verifies rebuild
hash equality and an executable smoke before publishing; each output file is
atomic, not a multi-file transaction. A failed bootstrap preserves published files.

## What closes over the compiler source

The assembled distribution is 89,611 bytes and305 functions:83 integer and
221 byte returns, with383 integer/380 byte parameters across definitions.
Assembly compacts identifiers, formatting/comments and selects nine shared lexer primitives from the full component and keeps
the compiler/runtime bodies. Compiler component byte spellings are explicit; independent oracle behavior is retained.
After assembly, every rebuild consumes the same Alchem file without host assembly
or source transformation.

The source profile supports typed integer/byte/string/boolean parameters and returns, scoped
bindings/branches, checked literals and wrapping arithmetic, direct/forward/mutual
calls, byte packing/count/index/concat/slice, strict boolean operators, recursive structural types/cases
and pinned-runtime grapheme APIs and complete native ELF construction.
Public native_compile(bytes)->bytes explicitly opts a module into native compiler
IO; a void main/0 remains for upstream source compatibility. Normal modules enter
main. The compiler builds this IO entry and all other instructions in Alchem.

Scaling required batched declaration/token traversal, balanced name search and
code assembly, saved function lengths (no second codegen pass), native bulk
slicing, and validated inline literal copies. The current profile allows 4,194,303
source bytes,512 functions, 128-element lists, 1024 body tokens, 16 live slots,
16 expression nesting levels, 65535 bytes per function and 512 KiB total code.
Source metadata uses u24 cursors and full type words; executable sizes retain bounded encodings. See spec/alchem-source-profile.md,
spec/compiler-scaling.md and docs/compiler-profile-inventory.md.

## Core components and library conversion

The standard build also compiles five native core tools through A3, including the
full lexer, decimal parser/formatter, expression evaluator, ELF encoder and
arithmetic compiler. The Alchem runtime emitter supports byte Enum.reverse,
take, drop and sum in addition to count/at/concat/slice. See
[core module coverage](core-modules.md) for protocols and remaining library gaps.

## General collections and additional library APIs

The next continuation supports distinct bytes/b[...] buffers, full-width typed
lists, integer/string/boolean-keyed immutable maps and named-function map/filter/
reduce. Enumeration sorts map keys like the pinned runtime. Further APIs span
Enum.join, Integer base formatting/digits/checked undigits, String.duplicate,
IO.write and System.pid/system_time/os_time/stop. See the collection/library
contracts and updated developer handoff for the remaining gaps.
